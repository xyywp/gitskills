快速开始

五步完成第一次练习

下面的命令以公开仓库为例，并假设你的默认分支是 master。没有写权限？先 Fork 一份到自己的账号，再把地址换成你的 fork。

  1. 01

    克隆仓库

    把仓库复制到本地，并进入项目目录。

    git clone https://github.com/xyywp/gitskills.git
cd gitskills
  2. 02

    新建练习分支

    不要直接在 master 上改。新建一个带描述的分支，失败了大不了删掉。Git 2.23 以前的版本可以用 git checkout -b 代替。

    git switch -c practice/hello
  3. 03

    做一点小改动

    往示例文件末尾追加一行，然后用 status 和 diff 观察 Git 眼中的变化。

    echo "hello git" >> yxx.txt
git status
git diff
  4. 04

    提交这次改动

    先暂存文件，再写一条清楚的提交说明。最后用 log 确认提交已经进入历史。

    git add yxx.txt
git commit -m "docs: 第一次练习"
git log --oneline -1
  5. 05

    推送并打开 Pull Request

    推送练习分支，然后到 GitHub 发起 Pull Request，把改动合回 master。如果只是在自己的 fork 里练习，不合并也完全可以。

    git push -u origin practice/hello

没有写权限？在 GitHub 页面右上角点 Fork，克隆自己的 fork 后推送；练习内容不会影响原仓库。

命令速查

21 条够用的 Git 命令

按场景分组，点击右侧按钮即可复制。先把常用的几条练到不用查，再慢慢扩展。

共 21 条命令

没有匹配的命令，换个关键词试试。

查看与比较

查看当前状态

随时确认哪些文件改了、哪些已经进入暂存区。

git status

查看未暂存的改动

逐行看工作区里还没 add 的内容。

git diff

查看已暂存的改动

提交前最后确认一次：这次到底会提交什么。

git diff --staged

图形化查看历史

把分支、合并与标签画成一张小图，排查历史很直观。

git log --oneline --graph --decorate --all

查看某次提交

看这次提交改了什么，以及完整的提交信息。

git show <commit>

提交

暂存文件

把指定文件放进暂存区；git add -p 可以逐块挑选。

git add <file>

提交暂存内容

提交说明写清楚「做了什么」，比写「update」有用得多。

git commit -m "说明"

并入上一次提交未推送时

补一个文件或改一下说明，保持提交历史干净。

git commit --amend --no-edit

分支与合并

列出本地分支

同时显示每个分支正在跟踪的远端分支。

git branch -vv

新建并切换分支

一个练习一个分支，互不干扰；老版本 Git 用 checkout -b。

git switch -c practice/hello

切回主分支

合并之前，先回到要接收改动的那个分支。

git switch master

合并分支

把练习分支的提交合并进当前分支，冲突时按 Git 的提示处理。

git merge practice/hello

同步远端

查看远端地址

确认 origin 指向哪里，尤其是 fork 之后。

git remote -v

拉取远端更新

只更新远端跟踪分支，顺手清掉已经删除的远端分支。

git fetch --prune

变基方式拉取

把本地提交接到远端最新提交之后，历史更线性。

git pull --rebase

首次推送并建立跟踪

之后在这个分支上直接 git push 即可。

git push -u origin practice/hello

撤销与暂存

放弃未暂存的修改

把文件恢复到最近一次提交的状态，改动会丢失。

git restore <file>

把文件移出暂存区

撤销 add，但保留工作区里的实际改动。

git restore --staged <file>

安全撤销已推送的提交

新建一次反向提交，不改写公共历史，适合协作分支。

git revert <commit>

暂存手头的修改

改到一半需要切分支时，先把现场收起来。

git stash push -m "wip"

恢复暂存的修改

回到原来的分支后，把刚才收起来的改动放回来。

git stash pop

练习路线

从会用到用得顺手

不必一次学完。按下面的顺序，每次只练一小块，遇到问题再翻命令速查。

Level 01 · 入门

日常四件套

先建立肌肉记忆：看状态、看差异、暂存、提交。这四个动作能覆盖大部分日常操作。

  • status
  • diff
  • add
  • commit
  • log

Level 02 · 分支

并行开发与合并

用分支隔离每次练习，再把它合回主分支。故意制造一次冲突，学会读懂冲突标记。

  • switch -c
  • branch -vv
  • merge
  • 冲突处理

Level 03 · 协作

和远端保持同步

从 fork、clone 到 push 和 Pull Request，走一遍真实的多人协作流程。

  • fork
  • remote -v
  • fetch --prune
  • pull --rebase
  • push -u

Level 04 · 进阶

整理历史与救场

学会用 stash 保存现场、用 revert 安全回滚，再用 reflog 把自己从误操作里捞出来。

  • stash
  • rebase
  • revert
  • cherry-pick
  • reflog

常见问题

练习时最容易卡住的几件事

大部分问题都能用 git status 的提示解决。先看清楚 Git 在说什么，再决定下一步。

我没有这个仓库的写权限，怎么练？

先在 GitHub 页面点 Fork，把仓库复制到自己的账号下，然后克隆你自己的 fork。这样 push 和开 Pull Request 都不会影响原仓库。

git clone https://github.com/<你的用户名>/gitskills.git
提交记录里的作者不是我，怎么办？

Git 的提交作者来自本地配置。在仓库目录里设置一次，之后的新提交就会用这个身份：

git config user.name "你的名字"
git config user.email "you@example.com"

去掉 --local 默认只影响当前仓库；如果希望全局生效，加上 --global。

改到一半要切分支，怎么办？

先把未提交的改动收进 stash，切到目标分支处理完，再切回来恢复：

git stash push -m "wip"
git switch master
# ……处理别的事情……
git switch practice/hello
git stash pop
合并时出现冲突，怎么处理？

用 git status 找到冲突文件，打开后会看到 <<<<<<<、=======、>>>>>>> 标记。保留需要的内容、删掉标记，然后：

git add <冲突文件>
git commit

不确定怎么合并时，先别删任何一边，把文件内容看清楚再动手。

已经推送的提交写错了，能改吗？

在共享分支上优先用 git revert <commit> 生成一次反向提交，而不是改写历史。只有在自己独占、没人基于它开发的分支上，才考虑强制推送，并且使用更安全的 --force-with-lease。

想彻底重来，怎么办？

最省心的办法是删掉本地目录重新克隆。如果只是想丢掉当前分支上的实验，先切回 master，再删除本地练习分支（未合并的改动会一并消失）：

git switch master
git branch -D practice/hello
